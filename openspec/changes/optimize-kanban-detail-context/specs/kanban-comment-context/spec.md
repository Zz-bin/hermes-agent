# Spec Delta

## Purpose

为 Kanban 评论保留真实交接时的上下文，使用户浏览历史时能够区分当时的负责人、工作区与明确关联的材料和当前任务属性，避免缺失数据被推断成事实，同时兼容既有评论。

## ADDED Requirements

### Requirement: 正式交接上下文
系统 SHALL 支持评论携带明确提交的正式交接标记、阶段与材料关联，持久化当时的负责人、状态与工作区。普通评论 SHALL 不成为默认交接。

#### Scenario: 新交接
- **WHEN** 提交正式交接并明确关联本卡附件
- **THEN** 后续卡片属性变化不修改交接快照，关联材料只展示指定附件

#### Scenario: 非法材料
- **WHEN** 提交其他卡片或不存在的附件关联
- **THEN** 拒绝写入，且不产生评论或事件

### Requirement: 兼容历史数据
系统 SHALL 保留旧评论原文，历史无快照字段 SHALL 显示未记录；不得用当前卡片属性、评论作者或时间猜测历史快照。

#### Scenario: 旧正式交接
- **WHEN** 浏览带明确正式交接头但没有快照的旧评论
- **THEN** 可以定位正文，右栏提示未记录，材料不自动取当前全部附件
