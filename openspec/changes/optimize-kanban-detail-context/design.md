# Design

## Context

见 proposal.md。用户已批准 `/home/capz/.hermes/openspec-kanban/designs/kanban-detail-v4.html`；2026-10-05 又确认“最新已完成评论”指最近正式交接，历史缺失不猜测。工作树 base `cbc569e23cb045b58b067f37cf5514feb44e0828`，不改运行实例。现有 Comment 仅 id/task_id/author/body/created_at；现有右栏编辑直接绑定当前 task。

## Goals / Non-Goals

**Goals:** 最小跨层扩展及可独立测试的上下文选择逻辑；复用原抽屉布局、Markdown、附件组件和主题。

**Non-Goals:** 写入策略强制、权限改造、通知系统改造、worker 启动修复、main 合并、部署、重启或自动追新。

## Decisions

- 使用可空 JSON `context` 列与版本 1 结构保存显式正式交接快照，迁移只加列不回填。CLI、工具、API 允许可选上下文输入，旧调用无变化。写入时服务器捕获任务负责人/状态/工作区；附件 ID 必须属于本卡，不能由客户端伪造快照。
- 明确的交接头按现行交接约定识别：请求批准、交付审查、审查结论、返工要求、阻塞求决、收尾交付；保留此前支持的别名（实现完成、审查通过、退回修改、需要输入、规划完成、请求审查）。前后端资格规则一致，仅匹配正文开头的 `【类型｜非空阶段】`（兼容 ASCII `|`），新写入省略 context 时自动捕获快照，显式 context 可声明阶段和材料；旧头仅分类，不推断或回填快照。普通讨论、用户决定、心跳、失败通知排除。分类与是否批准实现/部署无关，声明不是执行许可。
- 上下文只读分组置于当前属性上方，当前编辑保留为独立分组，避免历史模式误改任务。材料为明确关联的附件和显式声明的文件路径，不把任务全部附件冒充评论材料。可选 approval_scope/verification 原文在历史右栏按需展开；这是交接声明，不是服务器独立验证或执行许可。上下文为空时显示未记录。
- 摘要只标注运行来源并保持原文，不将 latest_summary 当审批或正式交接。
- 描述使用独立展开状态，编辑仍原字符串。评论的选择和筛选 reset 随 task.id；排序稳定按 created_at/id，不改变选择；筛选隐藏选择后清空。
- 不新增第三方依赖。后端通过安装环境 Python 跑本工作树测试；前端按锁文件安装独立依赖，避免触碰运行 PM。

## Risks / Trade-offs

- 旧评论无快照 → 明示未记录，不制造过去事实。
- 交接头约定有限 → 新写入支持显式 context；不做自然语言猜测。
- 部分材料只在正文路径 → 正文入口保留，附件快照仅显式 ID；不自动扫磁盘或上传。
- 上游经常更新 → 模块化 pure helpers、局部修改、准确提交、回归脚本和 patch；升级先检查冲突再测试。

## Migration Plan

开发验证只对临时 SQLite；运行数据库不操作。未来部署先备份数据库与版本。新增 nullable 列对旧读取兼容，旧版回退保留额外列和正文，新版上下文暂不可见。代码用 commit/patch 回退，禁止对真实数据库执行破坏性降级。
