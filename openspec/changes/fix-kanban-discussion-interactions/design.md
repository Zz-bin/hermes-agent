# Design

## Context

参见 proposal.md 的 Why 与 evidence/investigation.md。基线为6f515c4fc80e279f3078a90656eac21f53d5c57b；原生模拟复现保存而非打开、折叠不改变高度、选中隐藏折叠、发表区远在视窗外。处理人菜单现有但藏在属性区。用户新增“打开看板后风扇明显转动”只有候选负载证据，尚未产品根因确认。

这是待确认设计，不是获准实现。2026-10-11用户最新评论指定处理人在左上状态控件之前、跳转采用右侧悬浮目录并有悬停动画，新增评论图片粘贴报告。该指示已纳入第二版方案和演示，不等于整稿确认或实现许可；性能仍是调查候选，不擅自纳入已批准修复范围。第一版稿与证据原样保留。

## Goals / Non-Goals

**Goals:** 用现成详情组件与安全预览解决操作障碍；让阅读、定位、选中上下文和发表互不干扰；处理人入口与历史快照清楚区分；用可复现采样而非风扇声音推测性能。

**Non-Goals:** 不重做看板、不增加核心模型工具、通用文件管理器或状态数据库；不改既有审批和调度规则；本阶段不实现/合并/部署/重启/同步归档。默认设计不提供预约下一阶段字段，不自动用系统程序运行附件。

## Decisions

### 1. 复用附件预览，固定来源且只读

附件名打开一个由用户主动触发的只读预览，与独立↓保存按钮并列；两处列表共用组件。图片/SVG、PDF、文本/Markdown复用 existing LocalFilePreview/preview targets；HTML必须经已有清洗+CSP并置于无脚本沙箱，不能加载网络、跳转或执行。不能以local模式常规webview替代安全HTML附件预览。未知二进制只提示不能预览，提供保存，禁止自动执行默认程序。超限按已有读取限额处理（文本512KiB，HTML data URL16MiB）而非放开安全上限。

下载沿用captureGatewayFileDownload捕获原connection/profile。预览需同样绑定在详情取得时的来源，desktop-fs目前只读取活动连接，不能直接拼接路径后调用；在已有preview读取边界增加可选owner或读取器，限于这一个真实使用场景。任何跨连接/跨profile late response不覆盖新目标。旧后端缺stored_path时禁用并说明需要更新，不能猜路径；断线/权限/桥不存在明确报错和可重试关闭，不静默改到本机。

取舍：安全预览优于自动系统打开，避免远程路径误用和附件代码执行；用户若要求完整可执行HTML演示或系统默认程序打开，须另行明确行为/安全设计，不等同本稿批准。

### 2. 固定布局行，不遮盖正文

宽屏 main 改为 min-height:0 的纵向 flex：上部滚动正文+tabs；下部 composer flex-none。sidebar继续独立滚动。窄屏保留主栏/右栏顺序，使用一个整体内容scroller，composer作为其下方兄弟布局行（只挂一个编辑器，跨断点移动不丢草稿/焦点）。不要用fixed/absolute盖住正文，也不靠猜编辑器高度加固定padding。

输入框已有可增长高度限制，复用；在小高度窗口还限制编辑器占用，余下正文仍可滚。所有tab中保留发表入口，不把日志或活动变成评论；正在处理卡片的原“发送/记录并重新排队”行为保持，并保留取消/失败的草稿。发表评论成功才清空，失败保留草稿；部分成功（已发表但重新排队失败）不能重复发表。

### 3. 裁剪与上下文选择各自独立

长文用与描述相同思路的可见高度裁剪+overflow-hidden，不再对嵌套Markdown父层行裁剪。每条expanded独立且稳定按comment.id；短文完整显示；选中不强制展开，不隐藏展开/收起；跳转可显式展开目标。按钮是兄弟控件而非嵌套可选父按钮，click/keyboard不会选择上下文。非可见裁剪内容不得作为可Tab到的隐藏链接；实现需检查inert/摘要呈现方案，完整正文保留供展开、复制和上下文读取。

### 4. 楼层使用已有稳定ID

采用 #comment.id；可能非连续、跨卡有空缺，但不会因排序/过滤变化指向另一条。不加本次视觉顺序索引；无需数据迁移。分层头部（#id、作者、类型、时间），顶部主题细线/间距，左侧accent只表选中；定位focus-ring不是上下文选中。

第三版依据用户12:01评论及三张参考图，替代第二版的详情右缘按钮：入口贴讨论区左侧，缩起是一列短横线，当前视区楼层横线较长并有主题强调；悬停对应短线时展开楼层编号、作者和两行原文摘要，以及可滚动的编号列表。保留原编号输入用于精准定位。楼层左边线留在内容起点，目录在独立窄间距内，两者不重叠；宽窄屏优先左侧，只有具体版本无法避免视觉冲突时改讨论区右侧，不能改回右侧属性栏。第三版量测左侧没有冲突，因此不要求用户再次选择左右。参考原图仅表明静态形状与展开状态，动画时长并非截图证据。

讨论处于可见视区时，入口保持在该区侧边，不随某楼层滚走；活动/执行/日志或窄屏滚到属性区时隐藏，不冒充全详情导航。悬停以约120ms透明度和小幅位移展开，离开且无键盘焦点/点击保持时收起。不循环播放动画、不按鼠标每帧重算位置，减少动态效果关闭位移。点击可保持打开，触屏不用悬停；Tab/Enter可打开、选择条目，Esc仅关闭目录并还焦点。目录可滚动，列出原#id和作者，与当前排序一致；被过滤条目注明已隐藏，不重新编号。当前阅读楼层、悬停摘要、定位强调和上下文选择分开，不用目录高亮替用户选上下文。空评论时不画假短线，显示既有空状态。主路径：打开详情→讨论左侧短线→悬停/点击目录→选楼层或输入编号→定位头部→继续阅读/发表。

目标存在可见：展开→在实际scroller内定位完整头部→焦点→aria-live反馈。被过滤：确认显示全部后再定位或取消；显示全部不改已有选中，除非原筛选操作按旧规则已清空它。不存在：就地提示，不乱滚/乱选。窄屏入口仍贴讨论侧边，菜单不越过视窗且不覆盖发表控件；编辑器增长时菜单自动缩短并可滚动，顶部摘要重新打开可见。跳转后自动关闭，目标头部位于页头和发表区之间。实现复用现有Popover/Button和焦点边界，不新建通用目录框架。仅在实际滚动、尺寸变化和开关时更新位置，不保留静止循环。

### 5. 处理人入口与影响

当前处理人按用户指定放在详情页头左上、已有状态下拉框之前，右栏不重复一个可编辑处理人；窄屏同顺序换行，不挤掉关闭入口。历史处理人留在上下文且只读。菜单继续fetchProfiles与reassignTask，不新建分配系统；正在运行时显示“停止当前处理并重新分配？”确认，取消无请求，同一人无操作。非运行卡片不应无条件reclaim；按现有后端规则执行，成功读回状态/负责人，失败保持旧值并解释。加载名单、无可分配人、权限不足、pending和冲突均保留可恢复界面。菜单不把unknown profile交给调度器，不改变审批范围。

待用户决定（阻止实现）：是更改当前处理人供下一次合法调度使用（推荐复用），还是不打断当前工作、预约下一阶段？后者不是已支持行为，不能先造字段；若选后者先修订方案与规格再实现。

### 6. 性能报告的最低成本验证

新增第七项目前只纳入调查与待批准建议，不宣称修复。单次隔离A/B见performance-ab.json支持无限角度gradient动画为候选。批准调查后在准确已安装环境重复看板关/开、运行卡0/1/30、详情关/开、前台静止/后台对照，记录CPU/renderer TaskDuration、style/paint与请求/事件数量。采用稳定内容、同一时长、多次交替，先排除初次编译/加载。

如果动画复现显著持续耗时且静态对照解除，则提议仅将运行边框改为静态强调、心跳健康仍按原含义显示，隐藏/减少动态效果不持续绘制。若只出现一次加载峰值，则不强行改动，说明其范围；若不能复现则保留问题待客户端采样，不声称已解决。若发现重复socket/事件洪泛等，则先说明新证据与精确补丁范围，不扩大到全应用性能重构。任何需要用户真实客户端重启/远程接入的新操作另行申请。

### 7. 评论图片粘贴：先暂存，用户发表后上传

现有CommentComposer只有正文与发送；聊天extractClipboardImageBlobs已有图片提取/去重，看板uploadAttachment已有单文件上传和25MB上限，优先复用。输入框收到图片时先在底部编辑器内显示缩略图/文件名/移除按钮；允许只有图片或文字+图片的评论，普通文字粘贴继续正常插入。默认支持实际图片文件/截图的剪贴板载荷，不自动读取网页URL或网络HTML图片；无图片时不拦普通文本、不全局抢剪贴板。无图片载荷的平台提供已有选文件入口兜底；Mac/Windows系统剪贴板须实现后真测，浏览器合成事件不是系统粘贴证明。

发送时固定task/board/connection/profile来源，先逐张上传并记住返回附件ID，再发表正文。普通评论不能塞kind=handoff来冒充业务交接；建议正文用任务内附件引用（例如Markdown图片目标kanban-attachment:<id>）表达关联，无新增数据库字段。只在Kanban任务Markdown边界解析该引用，核实附件属于同卡、同来源，再走认证读取/图片预览；不改全局聊天MEDIA解析、不注入远程绝对路径/data URL、不允许直接外站图片请求。旧评论没有引用时仍走原渲染；旧端可读正文和附件名称，不要求改变旧快照。

超限/不支持图片不加入且保留已有草稿；上传/发表失败保留草稿与图片，已成功上传的ID继续使用，不重传。同来源上传部分成功必须说明已成为卡片附件，取消剩余草稿不删除已保存业务材料。发送pending禁重复点击；请求超时或切换连接后的结果不自动重发、不投向新卡，需在原来源读回核对是否已有附件/评论，再允许人工重试，不能把网络超时当未写入。发表成功才清空；运行中“记录并重新排队”在评论成功后才排队，排队失败只重试排队。该受限引用约定与普通图片粘贴仍为待批建议，不声称现有接口已支持图片评论全链路。

演示稿第二版使用本页FileReader读取用户主动粘贴的图片；缩略图与失败是模拟，无上传或任务请求。两份响应式模拟输入同步文字/图片，不代表产品应挂两个编辑器。示例截图按钮仅供无法粘贴时演示，产品不添加此测试按钮。

## Risks / Trade-offs

- [固定来源读取超出当前便利API] → 修改最窄现有preview/fs边界，local→remote→local及profile A→B→A验证；失败不可fallback读取错机器。
- [HTML演示脚本不可用] → 本附件打开路径选择安全只读；互动设计稿下载后由用户主动浏览器打开，用模拟内容；可执行附件另作决定。
- [稳定ID不连续] → “#”明确按原评论ID，定位校验目标存在，不使用数组位置。
- [窄屏布局重复编辑器] → 产品只保留一个草稿/输入实例；独立HTML稿为响应式演示两个同步输入，不代表实现架构。
- [运行中重新分配会终止当前人] → 明确确认与取消；不把当前分配伪装预约下一阶段。
- [Mac预览已有额外修复] → 保存目标版本并重新对照，不能用旧Linux基线覆盖；发布不在本次授权中。
- [性能样本不足] → 不作为已解决声明；本机累计CPU值不作即时CPU，优先准确环境、多次采样。

## Migration Plan

本变更设计不新增持久字段或数据迁移。实现只在保留开发树，隔离测试明确HERMES_KANBAN_HOME与绝对HERMES_KANBAN_DB并清理继承board，初始化前断言。真实业务卡只读，不上传探测数据或发表评论。未来发布需独立授权，保存准确旧客户端/后端版本和安装恢复材料；代码回退不恢复已发生的任务重新分配，不能用回退代码冒充停止worker的逆操作。当前未做发布、备份、重启或回滚。

## Approval Gate

分别批准：原六项与新增评论图片粘贴的方案行为、visual/interaction-v3.html视觉交互、是否授权上述实现、第七项只读性能定位/后续精确修复范围。最新三图反馈已授权此次目录规划修订，未解决当前重新分配与预约下一阶段的区别，也没有授予实现许可。合并/部署/重启/规格同步归档均未授权。实际客户端/后端主机和准确安装版本确认后方能进入实现验证。选择预约下一阶段或系统打开/执行HTML时需先修订相关规格，本草稿不是最终实现依据。tasks.md仍等待分配行为决定；第二版及第一版材料原样保留。
