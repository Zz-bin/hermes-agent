# Proposal

## Why

用户在现有任务详情页阅读材料和长讨论时，被直接保存附件、不可见的发表区、无效折叠及缺少楼层定位打断；补充报告还指出下一阶段处理人入口难以找到，以及评论不能直接粘贴图片。修复这些实际操作障碍，保留已接受的详情页框架与历史上下文，而非重做任务管理系统。

## What Changes

- 点击附件名称打开安全预览；图片、PDF、文本/Markdown、HTML分别复用现有预览能力。HTML保留沙箱限制，不能执行附件脚本。独立保存按钮继续走现有认证下载。不能预览的二进制/超限文件明确提示并提供保存，不悄悄弹保存框，也不自动执行系统程序。
- 评论发表区从讨论末尾移到主栏滚动区之外，窄屏位于整个内容滚动区之外；编辑器增长有上限，所有末尾内容可完整滚到发表区上方。保留活动/运行/日志页签，不新增说明面板。
- 用真实内容裁剪解决嵌套 Markdown 下折叠无效，选中与展开状态分离；每条展开、收起均独立工作。
- 复用当前评论 ID 作为稳定楼层标识（如 #108），加强头部、间距和单条分隔线，选中态保留强调色。
- 按用户最新三张参考图，楼层跳转采用讨论区侧边的短横线悬浮目录（不是右侧属性栏按钮或平铺面板）。优先左侧，给目录与楼层边线独立间距；仅在无法避免视觉冲突时改讨论区右侧。悬停短动画展开对应楼层摘要和编号列表，同时支持点击和键盘；目录内可选稳定编号或输入“跳至 #”。隐藏目标先提示并让用户取消或显示全部后定位；定位会展开和聚焦目标但不替用户选择右栏上下文。动画仅在打开/收起时发生，减少动态效果时禁用位移，不持续绘制。
- 按用户最新指示，当前处理人放到详情左上角、已有状态下拉框之前，不放右栏；历史负责人仍只读。默认方案为更改当前负责人供下一次合法调度使用，不引入预约下一阶段的新字段；正在处理的卡片必须说明“停止并重新分配”并确认，取消不执行。该语义仍须用户在批准时确认。
- 补充待批方案：评论输入框接收粘贴图片，先显示待发送缩略图并可移除，发表时复用附件上传；正文引用同卡附件稳定编号，楼层内可查看图片。普通文本粘贴不变，失败保留文字和图片，成功上传的图片重试不重复上传；不借用“正式交接”快照关联普通评论，不自动抓取外部图片地址。

## Capabilities

### New Capabilities

- `kanban-attachment-access`: 任务附件打开、独立保存及来源固定的安全边界。
- `kanban-task-assignment`: 当前负责人可发现的手动分配与正在执行时的明确确认。

### Modified Capabilities

- `kanban-detail-inspection`: 补充发表区布局、独立折叠、稳定楼层边界与跳转行为。此前变更定义该能力但尚未同步到主规格；本次增量仍使用准确相同路径，新增独立要求，不改旧规划或旧批准。

## Impact

预计修改 desktop Kanban 的 drawer、comment-thread、kanban.css、i18n、api及相关测试；附件预览复用现有 local-preview、preview-file、desktop-fs、安全 HTML 处理和认证下载，必要时只扩展来源参数，不增加新核心模型工具、第三方依赖或通用附件系统。既有后端分配接口已支持重新分配，默认不改变数据库结构、审批逻辑和调度状态规则。

当前仅获准调查/规划/交互稿，产品源码未改，未提交/合并/部署/重启/归档。原六项与新增图片粘贴属于本次待批行为；原第七项性能报告仍只调查，不算已确认修复，不继承旧卡许可。最新反馈只确认处理人位置、悬浮目录及动画方向，不是整稿或实现批准。基线 6f515c4fc80e279f3078a90656eac21f53d5c57b；保留 Mac 工作树 5ff7245eb571c4fee21f3bc7c67689863caabbad 仅用于只读对照，不能证明用户当前安装版本。用户实际客户端与后端版本须在实现前确认，材料与已知限制见 design.md 和 evidence/investigation.md。
