# Spec Delta

## Purpose

使用户在任务详情中找到当前任务处理人并安全地手动更改，同时区分交接当时的历史记录和现在可编辑的信息，避免隐藏的分配行为意外停止正在执行的工作或改变审批许可。

## ADDED Requirements

### Requirement: 当前处理人可发现且与历史区分
系统 SHALL 在详情左上页头、已有状态下拉框之前显示当前处理人入口，不将可编辑入口放到右侧栏或其他折叠属性内；历史上下文处理人 MUST 只读，改变当前分配不能改写历史。

#### Scenario: 查看和更改
- **WHEN** 用户进入详情并选择合法处理人
- **THEN** 当前入口位于左上状态控件前，窄屏保持顺序与关闭入口可用，成功后显示后端确认的当前人，历史快照不变

#### Scenario: 名单或请求失败
- **WHEN** 名单加载失败、无可分配人、权限不足或分配冲突
- **THEN** 给可恢复反馈并保持已有分配，不能显示虚假成功或向未知人调度

### Requirement: 停止运行需明确确认
系统 MUST 在改变运行卡片处理人前告知会停止当前处理并要求确认；取消无副作用。入口 MUST 不将当前重新分配表示为预约下一阶段，且不能授权实施或部署。

#### Scenario: 取消或确认
- **WHEN** 用户为运行卡片选择不同人
- **THEN** 先确认停止；取消不停止、不分配；确认后按现有任务规则执行并读回结果

#### Scenario: 非运行或同一人
- **WHEN** 用户给非运行任务更改处理人或选中原人
- **THEN** 不无条件停止处理；同一人不执行变更，其他更改遵守后端规则
